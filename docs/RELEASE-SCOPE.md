# Application Foundry release scope

Application Foundry is a local-first reverse recruiter for the applicant. A
stable release must support a complete path from existing records and job
discovery through tailored documents, application forms, and follow-up. The
applicant chooses how much submission automation to authorize.

| Release gate | Acceptance evidence | Current state |
| --- | --- | --- |
| Reusable document services | Share neutral extraction and document handling with ATS through a separately versioned repository/package that both projects can build and test independently. Keep applicant records and workflow permissions in their owning apps. | `document-extraction-dotnet` already exists as a private reusable repository. Application Foundry currently uses the same public parsing libraries locally because its public CI cannot fetch that private source; packaging/access and broader management reuse remain. |
| Document import | Import and review existing TXT, DOCX, and PDF résumés, cover letters, and source material; map useful facts into the profile and evidence library. Import the owner's legacy Access data through a previewed, reversible mapping. | TXT/DOCX/text-PDF extraction and saved text are implemented. A reviewed mapping step suggests contact details, summary, and bullet claims. Synthetic DOCX and corrected PDF mapping were checked on an independent Windows 11 clone; accepted DOCX evidence and the imported PDF persisted across app restart. Access migration and scanned PDF OCR remain. |
| Document export | Export the approved exact version of a tailored résumé and cover letter as usable DOCX and PDF from the Windows desktop app. | Web endpoints and desktop save dialog are implemented. Synthetic résumé and cover-letter versions were approved and saved as DOCX and PDF on an independent Windows 11 clone. The corrected PDF exporter preserved the résumé bullet through Windows save and reimport. Reimport previews of the saved cover-letter DOCX and PDF retained its greeting, role, evidence sentence, and sign-off; the PDF extraction wrapped one line. Visual layout and document quality still need acceptance. |
| Application form assistance | Reuse verified profile facts and prepared answers for employer-specific forms. Offer applicant-selected modes: review and submit personally, approve each submission, or automatic submission within applicant-defined rules. Record what was entered and sent. | Per-opportunity submission preference, applicant rules, and reviewed prepared answers are persisted locally. Saved profile name/email/phone can seed an answer for review. On an independent Windows 11 clone, the installed desktop app saved an approve-each-submission preference, synthetic rule, and reviewed profile email; all persisted after restart. The next installer saved a synthetic entered form value, removed it while unsent, and saved a replacement across restart. After both documents were approved, manual submission without field-value confirmation stayed blocked; confirmation marked the synthetic opportunity submitted and showed the entered value as sent. Submitted status persisted after restart. A local approval step binds the approve-each-submission choice to the exact employer, documents, rules, and recorded form values. On the independent Windows 11 clone, installer 0.1.64 blocked manual submission before packet approval, saved approval for a synthetic recorded value, retained it after restart, and required fresh approval after that value was removed. A subsequent synthetic test reapproved the changed packet, confirmed its recorded value, marked the opportunity Submitted, and retained status, approval, and value after restart. No employer form was contacted. Automatic mode has a local dry-run evaluator for exact organization and minimum-fit rules, HTTPS source, pre-submission status, and approved latest documents; unknown or duplicate rules block. Focused synthetic tests pass. On the independent Windows 11 clone, installer 0.1.67 matched a synthetic 60% fit opportunity under a 50% rule, blocked it under a 75% rule, and retained the saved blocking rule across restart. The UI states that no employer form was inspected or sent. A local form snapshot planner now proposes reviewed answer values only for supported, unambiguous fields on the saved posting's HTTPS origin and blocks incomplete or unsafe proposals; synthetic tests cover the contract. Browser form capture, applicant authorization to apply values, and actual employer form filling/submission remain. |
| Broader job discovery | Search more than one source, including roles beyond remote-only listings; support applicant filters, deduplication, source attribution, and local fit ranking. | Remote OK and a user-selected Greenhouse employer board can be searched with local required-keyword and minimum-fit filters; Greenhouse also supports a local location filter and nonremote roles. Results show source and location, remove duplicate URLs, and rank locally. Synthetic API tests pass. On an independent Windows 11 clone, installer 0.1.60 displayed ranked Remote OK results, then filtered the live Greenhouse board to London roles, showed Greenhouse source and location, and created a draft from one result. Employer-board selection is still manual rather than broad cross-board discovery. |
| Full workflow acceptance | On a clean Windows VM clone, install, import synthetic documents, create a profile, discover and evaluate jobs, tailor and export documents, exercise each form-assistance mode with fake data, record follow-up, restart and verify persistence, then uninstall. | Installer, synthetic TXT import, profile/evidence creation, manual job analysis, approval, résumé and cover-letter DOCX/PDF save, and persistence after upgrades were checked on an independent clone. Installer 0.1.60 also found Remote OK and Greenhouse jobs with the synthetic profile, created a Greenhouse job draft with both documents marked for review, and retained that opportunity after app restart. The current installer saved one form-assistance preference, a reviewed answer, and an entered field value across restart; unsent removal worked. Confirmed manual submission changed an earlier synthetic opportunity to Submitted and that status survived restart. Installer 0.1.62 upgraded that clone, scheduled a November 20 follow-up for the synthetic Greenhouse draft, recorded a synthetic status inquiry, cleared the date, and retained the activity after app restart. Installer 0.1.64 exercised approve-each blocking, packet approval, restart persistence, invalidation after changing a recorded value, and a positive approved manual submission with synthetic data. Installer 0.1.67 exercised automatic-rule local match/block checks and persistence. Employer form automation, broader automatic rules, document quality, clean install, and uninstall remain. |

Do not call the product release-ready until every gate has passing evidence and
the independent review described in [RELEASE-READINESS-REVIEW.md](RELEASE-READINESS-REVIEW.md)
is complete. The old Access records belong to the owner; do not commit them or
include them in test fixtures or release packages.
