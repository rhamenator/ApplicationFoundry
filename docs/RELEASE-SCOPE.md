# Application Foundry release scope

Application Foundry is a local-first reverse recruiter for the applicant. A
stable release must support a complete path from existing records and job
discovery through tailored documents, application forms, and follow-up. The
applicant chooses how much submission automation to authorize.

| Release gate | Acceptance evidence | Current state |

| Reusable document services | Share neutral extraction and document handling with ATS through a separately versioned repository/package that both projects can build and test independently. Keep applicant records and workflow permissions in their owning apps. | `document-extraction-dotnet` already exists as a private reusable repository. Its independent .NET 10 test suite passed 11/11 with real local Tesseract/Poppler OCR of a synthetic scanned PDF, and `dotnet pack` produced its package locally. Application Foundry still uses the same public parsing libraries locally because public CI cannot fetch private source; a controlled package distribution/build path, Windows OCR bundling and broader management reuse remain. The current Inno Setup desktop installer is unpackaged; [Microsoft documents that Windows.Media.Ocr requires package identity](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr?view=winrt-26100), so its WinRT OCR API cannot provide scanned-PDF support in this installer. A temporary compile proof was discarded after that constraint was verified; the feasible path is a trusted bundled local OCR engine and model through the private package, with Windows acceptance still required. |

Do not call the product release-ready until every gate has passing evidence and
the independent review described in [RELEASE-READINESS-REVIEW.md](RELEASE-READINESS-REVIEW.md)
is complete. The old Access records belong to the owner; do not commit them or
include them in test fixtures or release packages.
