# Application Foundry release scope

Application Foundry is a local-first reverse recruiter for the applicant. A
stable release must support a complete path from existing records and job
discovery through tailored documents, application forms, and follow-up. The
applicant chooses how much submission automation to authorize.

| Release gate | Acceptance evidence | Current state |
| --- | --- | --- |
| Reusable document services | Share neutral extraction and document handling with ATS through a separately versioned repository/package that both projects can build and test independently. Keep applicant records and workflow permissions in their owning apps. | `document-extraction-dotnet` already exists as a private reusable repository. Its independent .NET 10 test suite passed 11/11 with real local Tesseract/Poppler OCR of a synthetic scanned PDF, and `dotnet pack` produced its package locally. Application Foundry still uses the same public parsing libraries locally because public CI cannot fetch private source; a controlled package distribution/build path, Windows OCR bundling and broader management reuse remain. |
| Document import | Import and review existing TXT, DOCX, and PDF résumés, cover letters, and source material; map useful facts into the profile and evidence library. Import the owner's legacy Access data through a previewed, reversible mapping. | TXT/DOCX/text-PDF extraction and saved text are implemented. A reviewed mapping step suggests contact details, summary, and bullet claims. Synthetic DOCX and corrected PDF mapping were checked on an independent Windows 11 clone; accepted DOCX evidence and the imported PDF persisted across app restart. The studio previews one comma-delimited CSV or text table exported from Access in memory, showing its columns, record count, and first five rows without importing any records. UTF-8 and applicant-selected Windows-1252 are supported; an explicit legacy-encoding test preserves accented text and the euro sign. The applicant can assign each CSV column to a unique profile or evidence field and preview five mapped records without writing data; five focused synthetic parser/mapping tests pass. An in-memory evidence import plan checks every mapped row, deduplicates claims, rejects overlong claims and mixed profile mapping, and shows every proposed claim in an expandable review list. After explicit confirmation, the applicant can save the claims as a provenance-linked batch and undo that batch; the owner-scoped SQLite test verifies migration preserves existing evidence, duplicate import and cross-user undo are blocked, and undo leaves preexisting evidence intact. A separate one-record profile-field plan trims and validates mapped values, skips empty fields, and previews proposed changes. After explicit confirmation, selected fields are saved with before/after provenance; undo restores them only if none changed since import. A synthetic SQLite upgrade test verifies existing profile preservation, owner-scoped undo, conflict blocking, and preservation of unrelated edits. Twelve focused synthetic tests pass. The import path now distinguishes an empty TXT/DOCX from a textless PDF and gives a specific OCR-required message; six focused import tests pass. Windows acceptance of these import flows, direct Access file support, and in-app scanned PDF OCR remain. |
| Document export | Export the approved exact version of a tailored résumé and cover letter as usable DOCX and PDF from the Windows desktop app. | Web endpoints and desktop save dialog are implemented. DOCX résumé export now distinguishes the applicant name, section headings, and evidence bullets. A longer synthetic DOCX résumé rendered across five letter-size pages; text extraction recovered all 105 evidence bullets in order, with each later page starting at a complete bullet, and visual inspection found no clipping on page two. DOCX evidence paragraphs now stay together at page breaks; a 12-sentence synthetic boundary bullet moved intact to page two, while all 105 bullets and its repeated sentences survived text extraction. Fourteen focused tests passed. Professional résumé and cover-letter layout still needs Windows acceptance. |
| Application form assistance | Reuse verified profile facts and prepared answers for employer-specific forms. Offer applicant-selected modes: review and submit personally, approve each submission, or automatic submission within applicant-defined rules. Record what was entered and sent. | Per-opportunity submission preference, applicant rules, and reviewed prepared answers are persisted locally. Saved profile name/email/phone can seed an answer for review. On an independent Windows 11 clone, the installed desktop app saved an approve-each-submission preference, synthetic rule, and reviewed profile email; all persisted after restart. The next installer saved a synthetic entered form value, removed it while unsent, and saved a replacement across restart. After both documents were approved, manual submission without field-value confirmation stayed blocked; confirmation marked the synthetic opportunity submitted and showed the entered value as sent. Submitted status persisted after restart. A local approval step binds the approve-each-submission choice to the exact employer, documents, rules, and recorded form values. On the independent Windows 11 clone, installer 0.1.64 blocked manual submission before packet approval, saved approval for a synthetic recorded value, retained it after restart, and required fresh approval after that value was removed. A subsequent synthetic test reapproved the changed packet, confirmed its recorded value, marked the opportunity Submitted, and retained status, approval, and value after restart. No employer form was contacted. Automatic mode has a local dry-run evaluator for exact organization and minimum-fit rules, HTTPS source, pre-submission status, and approved latest documents; unknown or duplicate rules block. Focused synthetic tests pass. On the independent Windows 11 clone, installer 0.1.67 matched a synthetic 60% fit opportunity under a 50% rule, blocked it under a 75% rule, and retained the saved blocking rule across restart. The UI states that no employer form was inspected or sent. A local form snapshot planner proposes reviewed answer values only for supported, unambiguous fields on the saved posting's HTTPS origin and blocks incomplete or unsafe proposals. The studio now accepts a bounded, structure-only JSON form snapshot for a local preview, rejecting extra properties such as captured values; focused synthetic tests pass. A browser bookmarklet now captures field structure without entered values for local preview; a synthetic Chromium fixture verified the capture and omission of entered and hidden values. A ten-minute local authorization contract now binds an exact safe proposal to the job, form URL/fields, and reviewed values; changed or incomplete packets fail closed in focused synthetic tests. The studio now offers explicit authorization of the displayed proposal; it rereads the current saved job and rejects a changed packet, and keeps approval in memory for at most ten minutes. A packet builder now emits reviewed field values only while that authorization is current. A generic browser fill adapter rechecks the live URL and every field before setting values, and never submits; synthetic Chromium tests filled an exact form, blocked a changed form, and saw no submission. The studio now copies a current approved packet to the clipboard and offers the fill bookmarklet. After a matching fill, the browser helper copies a receipt of immediately observed values; a local validator matches that receipt to the exact approved job, URL, fingerprint, fields, and values. Synthetic Chromium and focused tests pass. The studio now previews a matching browser receipt, requires the applicant to confirm the observed values, and records all matching entries atomically as entered without marking the opportunity submitted; a focused synthetic SQLite test covers persistence and replay blocking. Installer 0.1.78 upgraded on the independent Windows 11 clone. A synthetic localhost HTTPS form was captured in Edge, previewed against two reviewed answers, explicitly authorized, filled through the clipboard packet, and returned an exact-value receipt. The applicant confirmed the observed values; both entries persisted after app restart as entered but not sent, while the opportunity remained ReadyForReview. The test clone was shut down gracefully and its ISO detached. A later 0.1.81 Windows check reproduced loss of a pasted form snapshot when a reviewed answer was saved. Installer 0.1.85 upgraded the independent Windows clone: the same synthetic two-field snapshot remained after saving a reviewed Availability answer; a new preview matched the saved email and Availability values. After exact-form authorization, saving another reviewed answer retained the snapshot but cleared the prior preview and authorization. No form was filled or submitted in this recheck. The local planner now blocks blank required reviewed answers and select lists with duplicate case-insensitive labels before the browser handoff, matching the browser helper’s fail-closed check; eight focused planner tests pass. Reviewed HTTPS portfolio links can now fill supported URL fields; the local planner and browser helper both reject invalid, non-HTTPS, or credential-bearing URLs. Fifteen focused form/packet/receipt tests and synthetic Chromium fill checks passed, including unsafe-URL blocking and no submission. Reviewed ISO start dates can now fill supported date fields; the local planner and browser helper reject malformed or impossible dates before entering any values. Eighteen focused form/packet/receipt tests and synthetic Chromium checks passed, including invalid-date blocking without submission. Employer-site compatibility and actual form submission remain unverified or unimplemented. |
| Broader job discovery | Search more than one source, including roles beyond remote-only listings; support applicant filters, deduplication, source attribution, and local fit ranking. | Remote OK, a user-selected Greenhouse employer board, and a user-selected [Lever employer site](https://github.com/lever/postings-api/blob/master/README.md) (global or EU) can be searched with local required-keyword and minimum-fit filters; the employer-site sources also support a local location filter and nonremote roles. Results show source and location, remove duplicate URLs, and rank locally. Synthetic API tests pass. On an independent Windows 11 clone, installer 0.1.60 displayed ranked Remote OK results, then filtered the live Greenhouse board to London roles, showed Greenhouse source and location, and created a draft from one result. All job feeds have a 16 MiB response cap before JSON parsing, including chunked responses without a Content-Length header. A combined search can now query Remote OK and one or both applicant-configured employer boards, keep results from available sources when another fails, deduplicate posting URLs, and rank matches together. Eleven focused synthetic discovery/merge tests pass, including Lever region, source attribution, local filters, URL validation, and no candidate data in requests. The studio can now read a pasted official Greenhouse or Lever board/posting URL, select its source, token, and Lever region without a network request, and prompt review of the employer name; ten focused parser/merge tests pass. The public [Arbeitnow API](https://www.arbeitnow.com/blog/job-board-api) adds Europe and UK job feeds, including nonremote postings; a read-only live check returned valid JSON from both endpoints and four focused synthetic discovery/registration tests passed. A full live feed check found that the Europe endpoint includes postings on Arbeitnow UK, France, Switzerland, and Netherlands domains as well as `.com`; the posting allowlist now accepts those exact official hosts, and a focused synthetic regression test passes. Arbeitnow single-source results now deduplicate tracking-query variants of the same posting path before ranking; a focused synthetic regression failed before the repair and passed after it. The combined search includes both feeds and applicant-selected employer boards, with source-failure fallback. Employer-site selection still requires the applicant to supply a link; Windows acceptance of the expanded combined search remains. |

Do not call the product release-ready until every gate has passing evidence and
the independent review described in [RELEASE-READINESS-REVIEW.md](RELEASE-READINESS-REVIEW.md)
is complete. The old Access records belong to the owner; do not commit them or
include them in test fixtures or release packages.
